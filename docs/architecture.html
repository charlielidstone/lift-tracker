The heart: local-first loop

  • • Every edit hits React state → localStorage cache first, so the app is instant and works offline.
  • • Online: writes go straight to Supabase. Offline: they queue in an outbox and flush on reconnect.
  • • On load it adopts the server copy UNLESS your cached "desired" differs from the last synced baseline — that one rule prevents stale-data freezes and the finished-workout wipe.

Layer discipline

  • • components/ = UI only. hooks/ = state/context. lib/ = pure, testable logic (no React).
  • • Business rules live in lib so they're unit-tested (vitest) — never buried in a component.
  • • Repos (*Repo.js) are the only place that talks REST to Supabase.

Where your feature plugs in

  • • Day type comes from schedule.js → resolveToday() (★), fed by ScheduleProvider + the schedule table.
  • • The toggle/time picker lives in the Settings tab (★) + SettingsProvider.
  • • A closed-app 6am push needs a new layer this diagram doesn't have yet: a push_subscriptions table (migration 009), a custom SW push handler, an Edge Function, and a cron trigger.
